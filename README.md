# Retail Sales Data Analysis Using MySQL

## Project Overview

This project focuses on cleaning and analyzing a retail sales dataset using MySQL.

The purpose of this project is to build practical SQL and data analysis skills by working with a realistic retail dataset and answering business-related questions.

The analysis started with basic SQL concepts and has progressively expanded into more advanced techniques, including:

* Data cleaning
* Exploratory Data Analysis (EDA)
* Aggregate functions
* Grouping and filtering
* `HAVING`
* `CASE WHEN`
* Subqueries
* Common Table Expressions (CTEs)
* Window functions
* `RANK()`
* `LAG()`
* `PARTITION BY`
* Month-over-month sales analysis

The analysis focuses on store performance, sales trends, foot traffic, advertising spend, returns, pricing, staffing, store size, and yearly/monthly sales patterns.

# 2. Data Cleaning

The dataset was checked for missing and empty values.

Missing values were checked using `IS NULL`.

Example:

```sql
SELECT *
FROM retail_sale2
WHERE ad_spend IS NULL
   OR promo_days IS NULL
   OR monthly_sales IS NULL;
```

Empty values were also checked in relevant columns.

After identifying empty values in `ad_spend`, the affected records were removed from the working table.

```sql
DELETE
FROM retail_sale2
WHERE ad_spend = '';
```

The cleaning process helped prepare the data for further analysis.

# 4. Store Performance Analysis

Store-level performance was analyzed using `GROUP BY`, aggregation functions, filtering, and sorting.

The analysis answered questions such as:

* Which 10 stores have the highest total sales?
* Which 10 stores have the lowest total sales?
* Which store has the highest average monthly sales?
* Which store has the highest total foot traffic?
* Which stores have the highest sales per employee?
* Which store has the largest store size?
* Which store has the highest number of parking spaces?

Example:

```sql
SELECT
    store_id,
    SUM(monthly_sales) AS total_sales
FROM retail_sale2
GROUP BY store_id
ORDER BY total_sales DESC
LIMIT 10;
```

Sales per employee was also calculated to compare store productivity:

```sql
SELECT
    store_id,
    ROUND(
        SUM(monthly_sales) / AVG(staff_count),
        2
    ) AS sales_per_employee
FROM retail_sale2
GROUP BY store_id
ORDER BY sales_per_employee DESC
LIMIT 10;
```

# 6. HAVING and Grouped Analysis

The next stage focused on using `HAVING` to filter grouped results after applying aggregate functions.

The following analyses were performed:

* Stores with average monthly sales greater than 4,000
* Stores with total monthly sales greater than 50,000
* Stores with average foot traffic greater than 4,000
* Stores with average advertising spend greater than 15,000
* Stores with average returns rate greater than 0.04
* Stores with more than 10 records
* Stores with both average monthly sales and average foot traffic greater than 4,000

Example:

```sql
SELECT
    store_id,
    AVG(monthly_sales) AS avg_month_sale
FROM retail_sale2
GROUP BY store_id
HAVING AVG(monthly_sales) > 4000;
```

This stage strengthened my understanding of the difference between `WHERE` and `HAVING`, particularly when working with aggregate functions.

# 7. CASE WHEN Analysis

`CASE WHEN` was used to transform numerical values into meaningful business categories.

### Sales Category

* `monthly_sales >= 4000` → High
* `monthly_sales >= 2000` → Medium
* Otherwise → Low

### Traffic Category

* `foot_traffic >= 5000` → High Traffic
* `foot_traffic >= 3000` → Medium Traffic
* Otherwise → Low Traffic

### Return Category

* `returns_rate > 0.04` → High Returns
* `returns_rate >= 0.03` → Medium Returns
* Otherwise → Low Returns

### Advertising Spend Category

* `ad_spend >= 20000` → High
* `ad_spend >= 10000` → Medium
* Otherwise → Low

A combined `store_performance` category was also created using `AND` and `OR` conditions:

* High sales AND high foot traffic → Excellent
* High sales OR high foot traffic → Good
* Otherwise → Needs Improvement

Example:

```sql
SELECT
    foot_traffic,
    monthly_sales,
    CASE
        WHEN monthly_sales >= 4000
             AND foot_traffic >= 5000
            THEN 'Excellent'
        WHEN monthly_sales >= 4000
             OR foot_traffic >= 5000
            THEN 'Good'
        ELSE 'Needs Improvement'
    END AS store_performance
FROM retail_sale2;
```

# 8. Subquery Analysis

Subqueries were introduced to compare individual records and store-level results against calculated values from the overall dataset.

The following analyses were performed:

* Records with monthly sales above the overall average
* Records with foot traffic above the overall average
* Records with advertising spend above the overall average
* Store(s) with the highest monthly sales
* Store(s) with the lowest monthly sales
* Records with sales greater than the maximum sales of Store 1
* Stores whose average monthly sales are greater than the overall average monthly sales

Example:

```sql
SELECT *
FROM retail_sale2

    SELECT AVG(monthly_sales)
    FROM retail_sale2

```

A more advanced example combined `GROUP BY`, `HAVING`, and a subquery:

```sql
SELECT
    store_id,
    AVG(monthly_sales) AS avg_month_sale
FROM retail_sale2
GROUP BY store_id
HAVING AVG(monthly_sales) > (
    SELECT AVG(monthly_sales)
    FROM retail_sale2
);
```

This stage helped strengthen my understanding of comparing individual or grouped results against overall dataset benchmarks.

# 9. Common Table Expressions (CTEs)

The project was extended to Common Table Expressions using the `WITH` clause.

CTEs were used to break complex SQL problems into smaller steps and make queries easier to understand.

The following analyses were performed:

* Records with sales above the overall average
* Stores with total sales above a specific threshold
* Average sales for each store
* Stores performing above overall sales and foot traffic averages
* Top stores based on total sales
* Stores with maximum monthly sales above a threshold
* Store-level total and average sales
* Sales-to-foot-traffic ratio analysis

### Example: Total Sales by Store

```sql
WITH cte_example AS (
    SELECT
        store_id,
        SUM(monthly_sales) AS total_sale
    FROM retail_sale2
    GROUP BY store_id
)
SELECT *
FROM cte_example
ORDER BY total_sale DESC
LIMIT 5;
```

### Example: Maximum Monthly Sales by Store

```sql
WITH cte_example AS (
    SELECT
        store_id,
        MAX(monthly_sales) AS max_sale
    FROM retail_sale2
    GROUP BY store_id
)
SELECT *
FROM cte_example
WHERE max_sale > 100000;
```

### Example: Sales-to-Foot-Traffic Ratio

```sql
WITH cte_example AS (
    SELECT
        store_id,
        SUM(monthly_sales) AS total_sale,
        SUM(foot_traffic) AS total_foot_traffic
    FROM retail_sale2
    GROUP BY store_id
)
SELECT *
FROM cte_example
ORDER BY total_sale / total_foot_traffic DESC
LIMIT 5;
```

CTEs helped me understand how a calculated result can be created first and then used in another query.

# 10. Window Functions and Ranking

The project was further extended to window functions, beginning with `RANK()`.

Window functions allow calculations to be performed across related rows while keeping the original rows in the result.

## RANK()

`RANK()` was used to rank sales records and stores based on different sales metrics.

### Rank All Records by Monthly Sales

```sql
SELECT
    monthly_sales,
    RANK() OVER (
        ORDER BY monthly_sales DESC
    ) AS sales_rank
FROM retail_sale2;
```

### Rank Stores by Total Sales

A CTE was used to calculate total sales for each store before ranking them.

```sql
WITH cte_example AS (
    SELECT
        store_id,
        SUM(monthly_sales) AS total_sale
    FROM retail_sale2
    GROUP BY store_id
)
SELECT
    store_id,
    total_sale,
    RANK() OVER (
        ORDER BY total_sale DESC
    ) AS sale_rank
FROM cte_example;
```

### Rank Stores by Average Monthly Sales

```sql
WITH cte_example AS (
    SELECT
        store_id,
        AVG(monthly_sales) AS avg_sale
    FROM retail_sale2
    GROUP BY store_id
)
SELECT
    store_id,
    avg_sale,
    RANK() OVER (
        ORDER BY avg_sale DESC
    ) AS sale_rank
FROM cte_example;
```

---

## Ranking Within Groups Using PARTITION BY

`PARTITION BY` was introduced to create separate rankings within groups.

### Rank Stores Within Each Month

```sql
SELECT
    store_id,
    monthly_sales,
    RANK() OVER (
        PARTITION BY month
        ORDER BY monthly_sales DESC
    ) AS sale_rank
FROM retail_sale2
ORDER BY month, sale_rank;
```

Here, the ranking restarts for every month.

### Rank Stores Within Each Year Based on Total Sales

A CTE was used to first calculate yearly total sales for each store.

```sql
WITH cte_example AS (
    SELECT
        year,
        store_id,
        SUM(monthly_sales) AS total_sale
    FROM retail_sale2
    GROUP BY year, store_id
)
SELECT
    year,
    store_id,
    total_sale,
    RANK() OVER (
        PARTITION BY year
        ORDER BY total_sale DESC
    ) AS sale_rank
FROM cte_example;
```

This ranks stores separately within each year.

---

## Top 3 Stores for Each Month

`RANK()` was combined with a CTE to identify the top 3 stores for every month.

```sql
WITH ranked_stores AS (
    SELECT
        month,
        store_id,
        monthly_sales,
        RANK() OVER (
            PARTITION BY month
            ORDER BY monthly_sales DESC
        ) AS store_rank
    FROM retail_sale2
)
SELECT
    month,
    store_id,
    monthly_sales,
    store_rank
FROM ranked_stores
WHERE store_rank <= 3
ORDER BY month, store_rank;
```

This demonstrated an important SQL pattern:

```text
Calculate ranking
       ↓
Store the result in a CTE
       ↓
Filter the ranking
       ↓
Return the top records from each group
```

# 11. LAG() and Month-over-Month Sales Analysis

The project was further extended by learning `LAG()`, another important SQL window function.

`LAG()` allows the current row to be compared with a previous row without requiring a self-join.

For this project, `LAG()` was used to compare monthly sales for each store.

## Previous Month's Sales

The previous month's sales were calculated separately for each store.

```sql
SELECT
    store_id,
    year,
    month,
    monthly_sales,
    LAG(monthly_sales) OVER (
        PARTITION BY store_id
        ORDER BY year, month
    ) AS previous_month_sales
FROM retail_sale2;
```

Here:

* `LAG()` looks at the previous row
* `PARTITION BY store_id` resets the calculation for each store
* `ORDER BY year, month` keeps the records in chronological order

The first month of each store has no previous month, so `LAG()` returns `NULL`.

---

## Sales Change Compared with Previous Month

A CTE was used to first calculate the previous month's sales and then calculate the difference.

```sql
WITH sale_data AS (
    SELECT
        store_id,
        month,
        year,
        monthly_sales,
        LAG(monthly_sales) OVER (
            PARTITION BY store_id
            ORDER BY year, month
        ) AS previous_month_sale
    FROM retail_sale2
)
SELECT
    store_id,
    month,
    year,
    monthly_sales,
    previous_month_sale,
    monthly_sales - previous_month_sale AS sales_change
FROM sale_data;
```

This shows whether sales increased or decreased compared with the previous month.

---

## Records Where Sales Increased

```sql
WITH sale_data AS (
    SELECT
        store_id,
        month,
        year,
        monthly_sales,
        LAG(monthly_sales) OVER (
            PARTITION BY store_id
            ORDER BY year, month
        ) AS previous_month_sale
    FROM retail_sale2
)
SELECT
    store_id,
    month,
    monthly_sales,
    previous_month_sale
FROM sale_data
WHERE monthly_sales > previous_month_sale;
```

This identifies months where a store's sales were higher than the previous month.

## Percentage Change from Previous Month

Month-over-month percentage change was calculated using:

```text
(Current Sales - Previous Sales) / Previous Sales × 100
```

SQL:

```sql
WITH sale_data AS (
    SELECT
        store_id,
        month,
        year,
        monthly_sales,
        LAG(monthly_sales) OVER (
            PARTITION BY store_id
            ORDER BY year, month
        ) AS previous_month_sale
    FROM retail_sale2
)
SELECT
    store_id,
    month,
    year,
    monthly_sales,
    previous_month_sale,
    (monthly_sales - previous_month_sale)
        / previous_month_sale * 100 AS percent_change
FROM sale_data;
```

This makes it possible to measure the rate at which sales increased or decreased from one month to the next.

---

## Sales from Two Months Ago

`LAG()` can also use an offset to look further back.

The following query compares the current month's sales with sales from two months earlier:

```sql
SELECT
    store_id,
    year,
    month,
    monthly_sales,
    LAG(monthly_sales, 2) OVER (
        PARTITION BY store_id
        ORDER BY year, month
    ) AS sales_2_months_ago
FROM retail_sale2;
```

The offset `2` tells `LAG()` to look two rows back within each store.

---

## Largest Monthly Sales Increase

The change between the current month and previous month was calculated first, followed by `MAX()` to find the largest increase for each store.

```sql
WITH sale_data AS (
    SELECT
        store_id,
        month,
        year,
        monthly_sales,
        LAG(monthly_sales) OVER (
            PARTITION BY store_id
            ORDER BY year, month
        ) AS previous_month_sale
    FROM retail_sale2
),
change_data AS (
    SELECT
        store_id,
        month,
        monthly_sales,
        previous_month_sale,
        monthly_sales - previous_month_sale AS sale_change
    FROM sale_data
)
SELECT
    store_id,
    MAX(sale_change) AS largest_increase
FROM change_data
GROUP BY store_id;
```

---

## Largest Monthly Sales Decrease

Similarly, `MIN()` was used to identify the largest decrease for each store.

```sql
WITH sale_data AS (
    SELECT
        store_id,
        month,
        year,
        monthly_sales,
        LAG(monthly_sales) OVER (
            PARTITION BY store_id
            ORDER BY year, month
        ) AS previous_month_sale
    FROM retail_sale2
),
change_data AS (
    SELECT
        store_id,
        month,
        monthly_sales,
        previous_month_sale,
        monthly_sales - previous_month_sale AS sale_change
    FROM sale_data
)
SELECT
    store_id,
    MIN(sale_change) AS largest_decrease
FROM change_data
GROUP BY store_id;
```

This stage helped me understand how `LAG()`, CTEs, and calculations can be combined to perform month-over-month business analysis.
